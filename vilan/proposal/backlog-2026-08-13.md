    STATUS: OPEN (design DRAFTED 2026-08-18 — method-resolution.md §13 awaits the owner's ruling; **BETA-CRITICAL**)
    `impl type T with Into<T>` matches every subject, so a user's own
    `impl Foo with Into<Bar>` loses to the blanket by declaration order
    — a wrong resolution from a clean compile, which the owner ruled
    counts as a miscompile for beta trigger (c). §13's 24-row probe
    table found the filing under-describes it: the headline shape is a
    false REJECTION, the silent miscompile is the unannotated call, and
    a second type-confusion miscompile (a `T: Conv<Baz>` bound emitting
    the `Conv<Bar>` body) involves no blanket at all — **so deleting
    std's blanket would not close trigger (c)**. Root cause splits in
    two: resolution keys on a bare trait id where B98's pair key and
    bound satisfaction both key on `(trait, arguments)`; and a genuine
    overlap falls back to declaration order. §13.5 recommends a
    specificity ordering (R1 arguments in the key, R2 expected-type
    selection, R3 subsumption ranking) over overlap rejection; §13.6
    asks six questions, Q2 (may an annotation steer impl selection) and
    Q3 (should the std blanket exist) being the load-bearing ones.
    13 `#[ignore]`d pins stand in `tests/inference.rs` under `b73_*`.
    History: backlog-2026-07-18.md §B item 73.

124. **An exhaustive `if`/`else` of bare `ret`s draws a false type error** (S–M)
    STATUS: OPEN (found 2026-08-12 by E61's lane — editing-dx.md §17.2)

    unification that a branch ending in `ret` contributes no tail value.

125. **NEW — the P21 standing pin: generic propagation through an annotated `.map<U>`** (M)
