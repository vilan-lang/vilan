34. **NEW — a self-referential local initializer overflows the analyzer**
    (S–M; found 2026-07-27 by the H7-ban slice's non-vacuity check,
    pre-existing) — `let x = x;` (a LOCAL binding whose initializer reads
    the binding being declared) sends the analyzer into unbounded recursion:
    `vilan check` aborts with a stack overflow, taking the process down —
    crash class, worse than a miscompile. Module-level self-reference is
    already a clean B33 cycle error; the LOCAL case has no guard. The ban
    slice's salvage token is currently load-bearing against one path into
    it (an unterminated string salvaged as `let prefix = prefix` would
    trigger it — why the salvage emits the scanned body, pinned). Root fix:
    the local-binding resolution must not resolve a name against the
    binding currently being declared (or must detect the cycle) — find the
    recursion site and break it with a clean diagnostic.

35. **NEW — `std::style` breakpoint rules emit in an order that lets narrow
    beat wide** (S; found 2026-07-27 building the vilan website) — a style
    with two breakpoints on the *same property*, `.sm(2col).lg(3col)`,
    emitted the `min-width: 640px` rule AFTER the `min-width: 1024px` rule
    in `client.css`; at ≥1024 both medias match, specificity ties, cascade
    order decides — desktop rendered the sm value. Media-conditioned rules
    should be emitted grouped in ascending `min-width` order so the widest
    matching breakpoint always wins (that is the entire mental model of
    mobile-first `min-width` chains). Workaround in the website: single
    breakpoint per property. Fix in `render_rule`/asset emission ordering +
    a pin that a `.sm(x).lg(y)` pair renders `y` on a wide viewport (assert
    on emitted-CSS rule order). Also worth a docs note in
    `docs/guide/styling.md` if any ordering caveat survives by design.

36. **NEW — the LSP's `[library]` context red-flags process-twin-only names
    in two-entry packages** (S–M; found 2026-07-27 building the vilan
    website) — in a package whose entries are `[entry.client]` (browser) +
    `[entry.server]` (node), a shared file importing `std::ui::render`
    (which exists only in the *process* twin) gets an editor diagnostic
    "cannot find `render` in the imported path" while `vilan build` is
    clean on both entries: the LSP analyzes the file under ONE platform

    per-entry analysis is the truth; the editor should either analyze
    per-reachable-entry and intersect diagnostics, or suppress
    platform-resolution errors for names that resolve under *some* entry
    the file is reachable from.

37. **NEW — `std::ui` cannot build inline SVG** (S–M; found 2026-07-27
    adding icons to the vilan website) — `view("svg")` goes through
    `create_element` = `document.createElement`, which produces an
    HTML-namespace element, so an inline `<svg>`/`<path>` tree silently
    renders nothing. The website works around it with pre-colored SVG
    files in `<img>` tags (loses `currentColor`/theme inheritance). Fix:
    `create_element` (or `view`) routes SVG tag names through
    `createElementNS("http://www.w3.org/2000/svg", …)` — either a tag
    allowlist or a `view_svg(tag)` entry point; the SSR twin needs the
    same tags to serialize with the `xmlns` attribute. Pin: an inline
    `svg>path` view renders with a nonzero client rect under the headless
    DOM e2e harness.

29. **Trait conformance is name-only; signatures unchecked** (M; **ARC ACTIVE

    parameter types, return type, generic members). Pre-existing; surfaced, not
    introduced, by C4.

## C. Memory model

*Frame: `claims-and-epochs.md` (2026-07-18) — the one law behind all of it (a claim is
valid while its owner's epoch is unchanged; views = static proof, handles = dynamic
check) and the closure decision: **C4 is the last major change to the memory model** —
everything else here is implementation or refinement within the frame.*

4. **Deterministic destruction** (L; **SHIPPED 2026-07-19, Tier 1 complete S1–S5** —
   ledger in `destruction.md`'s status block; Tier 2 = the counted class, specified in
   §10, builds with the native arc — **was the keystone; the memory model is now
   CLOSED per `claims-and-epochs.md` §4**) — scope-end destructors. The accepted design: a two-world
   partition — data stays rule-1 copying, untouched; a small **affine resource class**
   (declared `resource` + recursive containment) moves on binding/`own`, loans through
   the existing view conventions, and drops at its owner's scope end via
   `Drop { fun drop(&mut self) }` (Tier 1, on JS). `Shared`/`Owner`/`Disposable`
   deliberately stay data in v1; the counted class (`Shared` retain/release, `Weak` +
   `get`, counted closure environments) is Tier 2 — specified in `destruction.md` §10,
   built with the native arc. The design docs supersede this entry's earlier sketch.
   Unblocks C1, J4's free-spawn lint, real teardown in std, and the memory-model half
   of F3/F4.

1. **`Weak<T>`** (M; **blocked on counting** — C4 shipped 2026-07-19, so the blocker is
   now precisely Tier 2's refcounting (the native arc); fully specified in
   `destruction.md` §10, incl. the scoped `get(&self): Option<&T> borrows self` twin
   from `claims-and-epochs.md` §5a) — deterministic
   `upgrade() → None` needs a release event, which only exists once handles are
   refcounted; GC-timing `WeakRef` was rejected (2026-07-07). No JS-side driver today:
   the host GC collects `Shared` cycles, and observe-deletion is `Arena` generations'
   job.

2. **Dynamic rule-4 remainder** (sized 2026-07-18 → **folded into F4's native arc**) —
   cross-handle aliased writes (two `Shared` handles, one cell) need runtime
   generations / poisoned views; semantically empty on JS (nothing dangles, and E3 of
   `view-invalidation.md` already fences the across-`await` window). Build it with the
   native memory story, likely debug-mode-only.

6. **Geometry-effect inference — `bumps`, the twin of `borrows`** (**SHIPPED
   2026-07-19** — `rule4-completion.md`, commits d595ed2 (the effect) + 9b5e3cf (E2
   keys off it; both recorded E2 conservatisms cleared); residues recorded in the
   plan: generic verdicts are instantiation-independent-conservative, view-binding
   arguments under-approximate — both wait on no driver) —
   infer per function whether each `&mut` parameter (receiver included) is
   *content-stable* (field/element writes only) or *bumping* (may resize / reassign /

   inferred effect makes rule 4 precise (relaxation only — accepts more programs,
   changes no runtime behavior) and is the event classifier Tier 2's trap law and C2's
   generations key off. Fifth verse of the inferred-effect worklist (async, platform,
   contexts, `borrows`).

9. **NEW — `[service]` stores owning resources** (M–L; found 2026-07-19 by C4 S4a: the
   dispatcher collision) — a `[service]` struct with a resource field (`NotesStore { db:
   Database }`) is a resource by containment, and the generated dispatcher's per-`[rpc]`
   handler closures capture `self` — an R9 reject with no clean affine form (the
   handlers escape into the `Dispatcher`). v1's answer is the §9-blessed module-level

   demands it; do not weaken R9 for it.

10. **`borrows`-returned views are invisible to rule 4** (**SHIPPED 2026-07-19** —
    `rule4-completion.md`, commits 144d44e (root-set, + a chain-miscompile fix) +
    9b5e3cf (anchoring: call results + wrapped captures + the ForEach chain; ZERO
    std/corpus/docs/kolt fallout); the arena pin un-ignored; `Weak.get` (C1)
    inherits the anchoring by construction; was found 2026-07-19 by C8's rule-4
    pin as the biggest open static-model hole) — `compute_view_origins`
    tracks only direct `&place` bindings and view→view copies, and `Function.borrows`
    is a bare bool recording no projected root — so a call-returned view
    (`let v = list.at(0)`) or a wrapped-view `match` capture is never anchored, and
    E1/E2/E3 all miss invalidation under it (`list.push(x)` while `v` lives compiles;

    exercised direct views); semantically empty on JS, a hole in the single-conformance
    guarantee for native. Fix: the inferred `borrows` summary carries the projected
    parameter ROOT-SET; `compute_view_origins` seeds call results (mapping roots

    designed. Overlaps C6's `bumps` machinery (same summary). **C1's `Weak.get` ships
    the identical signature and inherits this until fixed.** `#[ignore]`d pin:
    `arena_mutation_under_a_live_get_view_is_rejected`.
